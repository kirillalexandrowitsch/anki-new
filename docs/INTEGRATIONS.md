# Файлы, медиа и интеграции macOS

## Матрица форматов

| Формат | Планируемый объём | Проверка готовности |
|---|---|---|
| CSV/TSV | UTF-8, BOM, выбор разделителя, quoted multiline, заголовки, mapping полей, теги | Round trip содержимого на fixtures с кириллицей, запятыми, переносами и кавычками |
| `.cardsdeck` | Собственные записи, варианты, теги и медиа; прогресс — по выбору | Версионированный manifest, хеши, перенос колоды между коллекциями |
| `.cardsbackup` | Полная точная копия собственной коллекции и parameter sets | Восстановление в отдельную папку и сравнение данных/истории/медиа |
| `.apkg` | Отдельная совместимость с Anki по утверждённой матрице | Реальные fixtures Anki, read/write round trip и отчёт неподдерживаемых возможностей |
| `.colpkg` / `collection.apkg` | Автоматическая замена всей коллекции не поддерживается | Распознавание и понятное предложение использовать другой экспорт; новая поддержка потребует отдельной задачи |

CSV не хранит точную историю и все варианты схем, поэтому переключатель «включить прогресс» для него недоступен с пояснением. Для APKG включение прогресса становится доступно только после T059/T064 и только для проверенных вариантов. Для родной резервной копии история всегда входит в состав. UI не должен показывать рабочей настройку, которую формат не реализует.

## Общий pipeline импорта

`выбор файла → получение доступа → определение формата → анализ → сопоставление → preview → решения о дублях → staging → финальное применение → отчёт`.

1. Открыть через NSOpenPanel/fileImporter, проверить содержимое, а не только расширение; release scope доступа после окончания чтения.
2. Парсер не пишет в рабочую коллекцию. Он строит versioned `ImportPlan` в staging, ограничивает ресурсы и записывает диагностику по строкам/объектам.
3. Preview показывает число Notes и Cards отдельно, колоды, медиа, warnings, несовместимые шаблоны и план изменения существующих данных.
4. Пользователь выбирает оставить / заменить / добавить отдельно. Дубликат по английскому слову — только кандидат: одинаковое слово может иметь разные значения. Стабильный внешний ID важнее текстового совпадения.
5. Опубликовать проверенные immutable media; затем атомарно применить записи из staging под exclusive operation lease. До финального commit Cancel оставляет рабочую БД без изменений. Процент анализа и финального применения показывать раздельно.
6. Отчёт содержит added/updated/skipped/errors и сводку потерь. Успех показывается только после commit. Ошибка не оставляет половину колоды в обычном списке.

Для больших объёмов parsing работает порциями. Начальный безопасный лимит одного применения — 100 000 Notes, 250 000 Cards, 2 ГБ распакованных данных, 100 000 media entries; это предложенные защитные пределы, калибруемые T063/T093. Превышение не приводит к неограниченному выделению памяти: показать лимит и возможность разбить файл. Если одна финальная транзакция на проверенном устройстве слишком долгая, T063 документирует shadow-database merge/activation; нельзя незаметно заменить атомарный импорт частично зафиксированными batch-записями.

## CSV/TSV

Использовать потоковый parser state machine, не `split("\n")`/`split(",")`. Обработка CRLF/LF, escaped quotes, multiline quoted cells. Несовпадение числа колонок — явная диагностика. UTF-8 по умолчанию; неподдержанная кодировка не подменяет русские буквы символами замены молча.

Предлагаемые колонки: `note_id`, `front`, `back`, `pronunciation`, `example_en`, `example_ru`, `tags`, `deck_path`, `type`. Системные UUID не принимать как доверенные ID без mapping источника. Относительные media paths принимаются только из явно выбранного media-root с проверкой containment; абсолютные пути и обход папок отклоняются. При экспорте для табличных редакторов предложить отдельный safe-spreadsheet mode для значений, начинающихся с формульных префиксов; его преобразования должны быть видимы и обратимы, не менять канонический текст silently.

## APKG

Anki различает пакеты колод и коллекций, legacy/modern варианты и наличие scheduling data. Следовательно, проверка ZIP-контейнера сама по себе не доказывает совместимость. [Описание форматов пользователю Anki](https://docs.ankiweb.net/manual/exporting).

T055 создаёт `APKG_COMPATIBILITY.md` с producer version, опциями экспорта, внутренними container/schema/compression variants и ожидаемым результатом. Начальный обязательный профиль — legacy-compatible deck package с Basic/Reverse/Cloze/Typed, локальными медиа и без исполняемых шаблонов. Прочие варианты явно распознаются и либо реализуются по fixtures, либо отклоняются до записи с инструкцией экспортировать совместимый вариант. Поддержку современных форматов расширять отдельной реализацией, если требуются дополнительные кодеки/схемы.

Внутренняя SQLite-модель приложения не копирует Anki schema. Import adapter создаёт собственные IDs и `external_ids`; повторный импорт не дублирует записи и не затирает локальные правки без preview. HTML-конвертер поддерживает ограниченное подмножество разметки; script, remote image/audio и произвольный CSS не исполняются. Непредставимые шаблоны показываются в отчёте, а не превращаются в пустые карточки с успехом.

Прогресс по умолчанию не импортируется. При его включении отдельно конвертируются сроки, фазы, lapses, параметры и history; неполные данные показываются до подтверждения. Отсутствующую память FSRS нельзя выдать за точную миграцию: предложить новый прогресс или явно обозначенную реконструкцию из поддержанной истории. Экспорт прогресса проходит обратную проверку в тестовой Anki, а не только повторное чтение собственным кодом. Копирование исходников Anki core не требуется; при его рассмотрении сначала отдельная проверка лицензий, а не скрытое добавление зависимости.

## Архивы и внешние данные

Проверять путь каждой entry после нормализации, запрещать абсолютные пути, `..`, symlinks и выход из staging. Считать фактически распакованные байты, число entries и отношение сжатия, не доверять одному заголовку ZIP. Предлагаемые начальные ограничения: отдельное изображение 20 МБ, аудио 100 МБ; большие файлы отклоняются с объяснением или обрабатываются после отдельного решения. Изображения декодируются с ограничением pixel dimensions; thumbnail через ImageIO без полной раскрутки огромного bitmap.

Ни архив, ни импортированный текст не запускают shell, AppleScript или JavaScript. Внутренние шаблоны — декларативная модель. Пользовательские SQL-фрагменты не сохраняются. Локальные данные не шифруются на уровне SQLite в первоначальном проекте; приложение не обещает собственное шифрование. Защита устройства и внешних копий определяется окружением пользователя.

## Медиа и произношение

AudioService выбирает: прикреплённый файл → доступный установленный голос en-GB/en-US → понятное состояние отсутствия голоса. Не гарантировать наличие конкретного голоса или его работу без загрузки системой. Проверять список доступных голосов; сеть не должна требоваться для уже локальных файлов. Использование синтеза основано на [AVFoundation speech synthesis](https://developer.apple.com/documentation/avfoundation/speech-synthesis).

Один playback coordinator предотвращает одновременное произношение из редактора и занятия. При смене карточки воспроизведение останавливается; автоматическое проигрывание зависит от настройки. Ошибка файла не блокирует саму оценку. UK/US выбирает доступный voice identifier и locale, а не меняет проверяемый перевод.

Запись микрофона — расширение T082. Запрашивать разрешение непосредственно перед первой записью, с purpose string и нужным entitlement. Отказ → объяснение и возврат; записанный файл сначала в staging. В waveform сравниваются две записи воспроизведением, оценок «точность 92%» нет. Удаление неприменённой записи убирает staging; Attach создаёт обычный MediaAsset.

## Backup и обслуживание

Автокопия при открытой программе: при первом изменении в новом учебном дне и перед миграцией/опасной массовой операцией; частоту можно уточнить настройкой. Не обещать ежедневный backup при полностью закрытом приложении без отдельно реализованного background service. Начальная retention policy: 7 ежедневных + 4 еженедельных проверенных копии; очистка только после создания и проверки новой, вручную закреплённые не удалять.

Проверка коллекции включает SQLite integrity/foreign keys, нарушения доменных связей, hash/существование медиа и пригодность схемы. Неиспользуемые файлы определяются по ссылкам всей коллекции, pending operations и undo batches, а не только выбранной колоды. Перед удалением — preview и подтверждение. Утерянное вложение можно найти заново через файл-панель. Отсутствие свободного места оставляет исходную коллекцию и предыдущие backups целыми.

## Системные возможности

UserNotifications хранит локальное календарное расписание напоминаний по разрешению; при отказе настройки времени сохраняются и показывается ссылка на системные настройки. Система может отложить/подавить баннер из-за Focus и пользовательских настроек; факт планирования не выдаётся за факт доставки. Внутренний центр сообщений отдельно хранит результаты собственных операций. [Документация локальных уведомлений](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app).

Sandbox entitlements первоначально: user-selected read/write и bookmarks там, где нужен длительный доступ. Microphone добавляется в расширении; сетевой доступ не нужен для главной функциональности. Конкретные entitlement keys сверяются с выбранным SDK. Системные Open/Save-панели, bookmarks и разрешения тестируются в sandboxed Release-сборке, а не только в Debug. [Доступ к файлам macOS](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox).
