# Учебная очередь T018

[Движок](REVIEW_ENGINE.md) · [Карточка задачи](tasks/T018.md)

`QueueBuilder` в CardsCore — чистый расчёт над согласованным `StudyQueueSnapshot`.
Он не пишет SQL, не считает FSRS-интервалы и не фиксирует оценки. Порт
`StudyQueueSource` получает свежий snapshot; `StudyQueueService.next` заново строит
очередь перед выдачей каждой карточки, проверяя generation. Ошибка источника,
неполный schedule или повреждённая иерархия не превращаются в успешную пустоту.
SQL-adapter, checkpoint и транзакция оценки подключаются в задачах занятия/RateCard.

Scope — вся коллекция либо множество корней с потомками. Пересекающиеся корни,
повторные одинаковые строки и CardID схлопываются; противоречивые строки дают ошибку.
Удалённая колода исключает поддерево. Активность Note/template поступает явно от
источника. Suspend/delete/suppressed/orphaned исключаются; burial задаёт ближайшее
доступное время. Для non-new обязателен finite dueAt. Приоритет: due learning и
relearning, due review, new; порядок внутри — dueAt, createdAt, CardID.

Учебный день рассчитывает StudyDayCalculator по явным now/timezone/rollover.
Дневные лимиты по умолчанию 20 new / 200 review; у колоды/предков могут быть более
строгие лимиты. Effective events несут сохранённые day key/timezone и путь колоды
на момент оценки (от колоды до корня). Потребление — множества CardID отдельно для
new/review, без epoch. Повтор Again, reset и move не удаляют потребление; voided
события исключаются. Все квоты применяются одновременно, preview резервирует места
для каждого возвращённого CardID, но не меняет журнал. Уже посчитанный CardID не
тратит повторное место в той же квоте. Learning/relearning проходят дневные и session
лимиты, чтобы можно было закончить начатое. Session limit ограничивает уникальные
CardID, включая ранее выбранные checkpoint IDs; skip исключает ID до конца сессии.

Sibling policy по умолчанию — bury до конца учебного дня первой эффективной оценки.
Событие хранит рассчитанный тогда siblingBuriedUntil (Calendar, а не +86400);
при Undo источник исключает voided событие. Bury действует и за пределами scope.
До первой оценки preview оставляет один вариант Note, следующий пересчёт использует
свежую историю. Политика allow разрешает siblings; lastPresentedNoteID откладывает
соседний вариант, когда есть другой готовый вопрос. Если других нет, его можно
показать: будущую карточку для заполнения очереди не подтягиваем.

Результат содержит ready, futureDue (CardID/availableAt), day и множество empty
reasons: noCardsInScope, unavailable, dailyLimit, sessionLimit, skipped, futureOnly.
Причины могут сочетаться; futureDue — ближайший известный срок после due/burial,
не обещание неизменности квот. Будущие review/new, заблокированные текущими квотами,
не получают выдуманное время сброса: потребуют нового расчёта на границе дня.
Готовый learning никогда не выдаётся раньше dueAt. UI «На сейчас всё» опирается
на futureDue; состояние ошибки остаётся ошибкой. Кнопки/экран/сохранение оценки
относятся к T019/T020, оригинальные PNG не меняются.
