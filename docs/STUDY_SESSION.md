# Экран занятия T019

[Движок](REVIEW_ENGINE.md) · [Очередь](STUDY_QUEUE.md) · [Архитектура](ARCHITECTURE.md)

`StudySessionModel` — MainActor-автомат loading/question/answer/committing/paused/completed.
`StudySessionService` — Core-порт чтения следующего вопроса и подтверждения команды оценки.
Адаптер обязан перечитывать доступность перед показом, проверять generation/revision перед записью,
возвращать успех только после commit и поддерживать идемпотентность commandID.
SQL adapter и атомарная запись/Undo реализованы в [T020](REVIEW_TRANSACTIONS.md); воспроизведение — в T021.
«Сегодня → Начать занятие» использует реальную коллекцию. Отдельное «Сегодня → Пробное занятие» явно запускает только синтетические карточки
в памяти. Пробный режим не читает и не меняет коллекцию, не обещает сохранения прогресса и не показывает
выдуманных интервалов/статистики. Начало происходит только по явному действию пользователя.

Допустимые события:

| Состояние | События |
|---|---|
| loading | результат → question/completed; ошибка → loading с Повторить; выход |
| question | reveal → answer; skip → loading; pause → paused; запрос выхода |
| answer | grade → committing; pause → paused; запрос выхода |
| committing | успех → loading → следующий скрытый question/completed; ошибка → тот же answer |
| paused | resume → точное предыдущее question/answer; запрос выхода |
| completed | закрытие; отмена последнего пропуска → loading |

Подтверждение выхода блокирует события основного экрана. Escape отменяет подтверждение,
из pause возвращает прежнее состояние, из вопроса/ответа открывает подтверждение.
Закрытие родительского окна и ⌘W используют тот же gate. `StudyCommands` в app scene
получает focused scene action и добавляет нативную команду «Закрыть занятие». Во время committing выход запрещён.
После закрытия экрана запоздалый async result не меняет автомат.

До reveal ни ответ, ни четыре оценки не входят в view/accessibility tree. После reveal ровно
Снова / Трудно / Хорошо / Легко. Space/1–4 маршрутизируются только из окна занятия,
без модификаторов, вне NSTextInputClient и только в допустимом состоянии; key repeat игнорируется.
При pause содержимое карточки заменяется панелью паузы. Следующая карточка всегда скрыта.

Команда содержит CardID, expectedRevision/epoch, Grade, event time, duration/seed и стабильный commandID.
Реальный service добавляет sessionID. Undo возвращает предыдущий ответ раскрытым с новой revision;
отменённые оценки исключены из effectiveStatistics и дневных квот.
При ошибке она остаётся pending: отдельная кнопка повторяет ту же команду, новые оценки
запрещены. После подтверждённого commit ошибка загрузки следующей карточки повторяет только
чтение; оценка больше не отправляется. Счётчик обозначает число подтверждённых оценок,
а не выученных карточек. Ошибки загрузки не превращаются в «всё повторено».

Skip добавляет CardID в session exclusions, не вызывает rate и показывает обратную связь
с отменой. Undo skip удаляет исключение и запрашивает свежую карточку через сервис; ответ
снова скрыт. Конец различает просмотр доступных, пустую очередь и будущий срок.
При futureDue кнопка «Проверить очередь» повторно читает сервис; UI не подгоняет сроки.

## Checkpoint и итоги T022

Реальная сессия сохраняет versioned checkpoint в `study_sessions.scopeJSON` (scope очереди
по-прежнему в studyPolicyJSON): текущая Card, question/answer, prior-to-pause,
исключения Skip и последний пропуск. Записи упорядочены; оценка ждёт предыдущий
checkpoint, а ReviewLog/расписание остаются атомарной командой T020. При восстановлении
счётчики и grade distribution читаются из effective ReviewLog, текущая Card повторно
проверяется на доступность, ответ скрывается. Сохранённая пауза остаётся паузой.

Очередь без доступных вопросов показывает промежуточные итоги; Undo и проверка будущего
срока остаются доступны. Явное закрытие итогов сохраняет completed/endedAt; подтверждённый
досрочный выход сохраняет abandoned/endedAt и итоги, не удаляет оценки. Новый запуск после
завершения создаёт новую сессию. Ошибка checkpoint не выдаётся за сохранение: видна отдельная
ошибка и повтор; финальное закрытие разрешено только после успешного сохранения.

Активное время измеряется монотонным источником. Heartbeat раз в секунду сохраняет только
foreground question/answer; пауза, exit confirmation, committing, сон, отсутствие активности
60 секунд и разрыв heartbeat свыше 5 секунд не учитываются. Response time ограничен 60
секундами. Время сессии не вычитается при Undo: это реально затраченное время; статистика
эффективных оценок исключает отменённый response time. Время между процессами не добавляется.

Успешный повтор checkpoint возобновляет прерванное чтение очереди (в том числе после
Skip/Undo Skip), а не оставляет loading без продолжения. Если checkpoint не позволил
подготовить оценку, исходная pending-команда остаётся доступной отдельной кнопкой
повторной оценки после сохранения прогресса; скрытой автоматической оценки нет.
