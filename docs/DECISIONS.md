# Технические решения

[Оглавление](README.md) · [Источники](SOURCES.md)

Статус: приняты для предложенного плана разработки, реализация ещё не проверена сборкой. Изменение решения оформлять записью: причина, альтернативы, затронутые задачи, миграция и проверка.

| ID | Решение | Рассмотренные варианты и последствия |
|---|---|---|
| ADR-01 | Swift + SwiftUI, AppKit по необходимости | Соответствует нативному Mac UX. Electron/Tauri и веб-интерфейс не дают преимуществ этому локальному проекту, которые оправдали бы второй UI-стек. AppKit допустим для сложной таблицы/редактора после проверки SwiftUI-прототипа. |
| ADR-02 | macOS 15+ и arm64 в первой ветке | Это предлагаемая граница поддержки; на macOS 26 нужно отдельно проверить поведение новых системных материалов. Не имитировать новый OS-стиль на старой системе ценой недоступных контролов. Intel и более старые ОС требуют отдельной проверки. |
| ADR-03 | SQLite + GRDB как единственное основное хранилище | SwiftData/Core Data возможны, но здесь важны явные миграции, поисковые запросы, переносимые snapshots, транзакционные оценки и массовые операции. Цена выбора — писать и тестировать SQL/схему самостоятельно. Не вести параллельно SwiftData и SQLite для одних сущностей. |
| ADR-04 | Модульное приложение и ручная передача зависимостей | Core изолирован от UI и библиотек. MVVM используется для экранов, use cases — для правил. Без DI-контейнера, глобального store на всё приложение и обязательного стороннего state framework. |
| ADR-05 | FSRS-6 в адаптере `swift-fsrs` | На момент проверки README содержит путь включения FSRS-6 с 21 параметром и отдельно defaults для FSRS-5. Поэтому T003 фиксирует ревизию, конфигурацию и контрольные векторы; не использовать случайный default. При несовпадении результатов — остановить интеграцию и оформить замену реализации, не изобретать интервалы в UI. [Первичный источник](https://github.com/open-spaced-repetition/swift-fsrs). |
| ADR-06 | Note отдельно от Card; журнал оценок отдельно от текущего расписания | Обратные карточки и пропуски имеют независимый прогресс; общие поля не дублируются. Это требует явного поведения удаления и регенерации вариантов. |
| ADR-07 | Локальная коллекция — папка с SQLite и медиа | Файлы контролирует приложение; sandbox доступ к внешним папкам через user selection и bookmarks. Рабочую SQLite-базу не размещать в сетевой/iCloud-синхронизируемой папке. Обмен — через закрытые экспортные архивы. |
| ADR-08 | Собственный архив для точной копии; APKG — отдельный адаптер | Родной архив восстанавливает собственные схемы и FSRS-параметры. APKG проверяется на ограниченной матрице, не служит внутренней базой. Для неподдерживаемого шаблона нужен отчёт до записи. |
| ADR-09 | Сначала offline; без встроенного сервера | Аудио прикреплённое или доступный системный голос; слово дня из локальных данных. Нет скрытых ключей API и автоматической отправки слов/микрофона. |
| ADR-10 | Локальное личное приложение | Пользователь делает приложение только для своего MacBook. Финальный результат — запускаемая Release `.app`; платная программа разработчика, публичный DMG и notarization не являются условиями завершения. Локальная подпись и разрешения проверяются на этом Mac. Sandbox сохраняется как технический выбор проекта; проблемы его конкретных entitlements решаются и проверяются локально. |
| ADR-11 | История и Undo через явные команды | Оценка, расписание и очередь записываются одной транзакцией. Undo компенсирует последнюю допустимую команду; reset начинает новую эпоху расписания, не фальсифицирует старую историю. |
| ADR-12 | Поэтапный выпуск без удаления расширений из плана | Первая вертикаль нужна для проверки базы и UX; полный набор 42 листов остаётся в трассировке и задачах. Детали реализации могут требовать уточнения, но не скрытого исключения состояния. |
| ADR-13 | Ноль дополнительных платежей | Кроме уже оплаченного Codex проект не требует новых расходов: инструменты и зависимости бесплатны, данные локальны; сборки/тесты локальны либо на бесплатных стандартных public runners, GitHub используется для кода и CI. Платные API, сервисы, trial с оплатой, платный CI и покупка credits не допускаются. Полная политика — [BUDGET.md](BUDGET.md). |

## Решения, уточняемые в первых задачах

Результат T001: [окружение](ENVIRONMENT.md) фиксирует полный Xcode/SDK, временные bundle IDs, пустой team, локальную ad-hoc подпись и доступные тестовые системы. T003 фиксирует версии GRDB, FSRS, ZIPFoundation и проверяет FTS5. T055 фиксирует список реально поддерживаемых вариантов APKG. T093 измеряет производительность на конкретном Mac. До соответствующих проверок цифры и API-сигнатуры в документах являются проектными контрактами.

| ADR-14 | Автономные PR dev → stage → main | Пользователь разрешил Codex самостоятельно создавать PR, исправлять CI и merge при SUCCESS quality/macos, выполненных критериях и сохранённом отчёте. Ветки защищены также от обхода владельцем; платные проверки и обход защиты запрещены. Репозиторий публичный с подтверждённым пониманием сохранения чужих копий. |
