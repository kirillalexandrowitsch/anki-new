# Проверка качества и выпуск

[Оглавление](README.md) · [Порядок разработки](ROADMAP.md)

Обязательное финансовое условие: [BUDGET.md](BUDGET.md). Сборки и тесты выполняются локально и на стандартных бесплатных public runners. Платные API, новые подписки и larger runners запрещены.

## Определение готовой задачи

Код находится в соответствующем модуле, выполняет конкретные критерии карточки задачи, проходит относящиеся к изменению проверки. Нет фиктивного success, hardcoded статистики вместо реальных запросов и активных кнопок для ещё неподдержанного действия. Изменённый контракт отражён в документации. Доменная или файловая логика имеет проверку наиболее опасного пути; простая правка отступа не требует теста, повторяющего реализацию.

Поведение проверяется по FLOWS.md, визуальное сходство — по соответствующим PNG. Сравнение с растром не заменяет проверку работы клавиатуры, persistence и ошибок. В тестах фиксировать clock, timezone, locale, scheduler parameters, seed и размер окна.

## Слои тестирования

| Слой | Что проверять | Инструмент |
|---|---|---|
| Core | Генерация вариантов, валидация, StudyDay, очередь, FSM, quota, Undo | Swift Testing, deterministic clock |
| Scheduler | Four-grade vectors, learning/relearning, повторяемость, pinned reference outputs | Параметризованные тесты и versioned fixtures |
| Persistence | Транзакции, foreign keys, revisions, идемпотентность, миграции, concurrent reads | Временная file SQLite и выбранный GRDB; in-memory только для подходящих unit cases |
| File operations | Import staging, archive limits, snapshot+media, rollback, missing files, insufficient space | Изолированные временные папки и fault injection |
| UI | Создание → редактор → раскрытие → оценка → перезапуск; настройки и диалоги | XCUITest; устойчивые accessibility identifiers |
| Визуальные | Светлая/тёмная, крупный текст, обычное/компактное окно | Ручное сравнение, выборочные snapshots стабильных компонентов |
| Личная установка | Запуск, sandbox, bookmarks, установка/замена версии | Локальная Release .app на ноутбуке владельца |

## Обязательные сценарии

1. Двойное нажатие оценки, повтор commandID после ошибки и падение после commit создают одну оценку.
2. До reveal кнопки и shortcuts 1–4 не оценивают; Space не ломает многословный ввод в поле.
3. Undo восстанавливает расписание и корректные счётчики, но не перетирает более новую правку другого окна.
4. Skip, bury, suspend и reset имеют разные последствия; никаких скрытых оценок.
5. Прерывание Save/import/backup/restore до и после критических шагов не оставляет опубликованные ссылки на отсутствующие файлы или потерянную рабочую коллекцию.
6. Миграция из каждой поддержанной схемы проходит; более новая неизвестная схема не открывается на запись.
7. Дневная граница, DST, смена timezone и сон Mac не дублируют лимиты и историю.
8. Удаление последней Card и последующий Save Note не воскрешает suppressed variant; undo в первые 5 секунд возвращает содержимое.
9. Parent deck со вложенными колодами считает CardID один раз; перенос не переписывает историческую статистику.
10. Импорт одного пакета дважды не создаёт двойников по внешнему ID. Другой перевод того же слова не теряется.
11. Повреждённые ZIP/медиа, path traversal, большие размеры и ошибки прав завершаются понятным отказом до повреждения данных.
12. Несохранённый редактор + смена коллекции/закрытие окна соблюдает Save/Discard/Cancel; запоздавший async callback старой коллекции игнорируется.

## Предлагаемые бюджеты производительности

Это цели, не результаты измерений. Базовая тестовая машина: MacBook Air M1/8 ГБ либо сопоставимый Apple Silicon, без Rosetta, Release-сборка. Записать модель/OS/SSD/версию приложения в каждом benchmark.

| Сценарий | Первоначальная цель |
|---|---|
| Cold launch с 50 000 Card и 1 млн ReviewLog | Рабочая оболочка до 2 с, данные по мере готовности |
| Поиск / смена фильтра 50 000 Card | p95 до 250 ms после 150 ms debounce |
| Оценка → новый вопрос | p95 до 150 ms без учёта выбранной анимации |
| Скролл библиотеки | Отсутствие устойчивых зависаний, окно кадров около 16,7 ms на 60 Hz |
| Основная память без огромных медиа | Ориентир до 300 МБ, профилировать рост и утечки |
| Idle | Нет polling всей базы и непрерывной перерисовки графиков; измерить Energy Log |

Для импорта публиковать замер строк/сек и peak memory вместо выдуманного универсального срока. При провале измерений оптимизировать запросы/индексы, page size, decode/cache и наблюдения, прежде чем менять весь стек. Большие базы и медиа создаются synthetic generator, не личной коллекцией пользователя.

## Доступность и локализация

Все основные сценарии выполняются клавиатурой; порядок фокуса и возврат из диалогов проверены. VoiceOver получает label/value/state, включая направление карточки, кнопку звука, очередность оценок и сообщения об ошибках. Графики имеют текстовый эквивалент. Статус не зависит только от цвета. Проверять контраст реальных контролов, увеличение текста, Reduce Motion и Increase Contrast. Сертификацию доступности без отдельного аудита не заявлять.

Russian/English строки в String Catalog. Множественные формы, даты, числа, интервалы и длительности форматируются через системные форматтеры, а не конкатенацию «1 карточек». Английский учебный контент и перевод интерфейса независимы. Поддержка новой локали не меняет нормализацию IDs/ключей поиска.

## Сборка и доставка

T001 проверяет полный Xcode через `/Applications/Xcode.app/Contents/Developer`: Xcode 27.1, Swift 6.4, SDK macOS 27.0; локальная система macOS 27.0.1 arm64. Команды воспроизведения, настройки Swift 6/macOS 15.0/arm64 и ограничения проверки минимальной ОС — в [ENVIRONMENT.md](ENVIRONMENT.md). `python3 scripts/check_environment.py` собирает и запускает временный пустой app target с локальной ad-hoc подписью; это отдельная проверка окружения до появления основного приложения.

В T002 создаются shared schemes для приложения и тестов. Package tests запускаются из локального CardsKit; UI tests — через app scheme на macOS. Файлы редактируются в Codex/VS Code; полный Xcode необходим для выбранных инструментов xcodebuild и XCUITest, пользоваться его IDE ежедневно не требуется. [Xcode command-line reference](https://developer.apple.com/documentation/xcode/xcode-command-line-tool-reference), [Swift в VS Code](https://docs.swift.org/latest/documentation/userdocs/).

Git и публичный origin с защищёнными dev/stage/main настроены при подготовке проекта; состояние и URL — в [PROJECT_SETUP.md](PROJECT_SETUP.md). Реальные команды swift test/xcodebuild test фиксируются после создания app target, сейчас эти проверки не объявляются выполненными. Источник статусов — backlog.json; порядок работы чатами — [AI_WORKFLOW.md](AI_WORKFLOW.md).

Перед основной бетой: сквозной сценарий, backup/restore, файловые разрешения, доступность и compatibility report. Финальная личная поставка: arm64 Release .app, постоянный bundle ID, локальная подпись/entitlements по необходимости, установка и запуск на ноутбуке владельца. Developer ID, платная программа разработчика, notarization, DMG и App Store не обязательны. Проверять только реально используемую macOS обязательно; другие устройства и версии — дополнительная совместимость, которую нельзя объявлять проверенной без выполнения.

Обновление — локальная замена приложения с сохранением коллекции вне app bundle. Перед миграцией создаётся проверенная копия; старая сборка не обещает читать новую схему. Самообновление и Sparkle не входят в план. Откат Git возвращает исходники, а откат учебной базы требует совместимой сборки и backup.

## Общая приёмка полного проекта

Все 174 позиции трассировки (6 экранов + 168 панелей) имеют задачу и проверку либо явно документированное согласованное изменение. Все ошибки из листов 18/24/36/42 воспроизводимы на fixtures. Основной сценарий работает offline. Совместимость APKG соответствует опубликованной матрице. Данные сохраняются между запусками, проверенная копия восстанавливается, статистика согласована с журналом. Текстовые и визуальные материалы не обещают несуществующий сервис, автоперевод или оценку произношения.

T012: единая локальная проверка, synthetic seed, TestClock, fault hooks и безопасная диагностика описаны в [TESTING.md](TESTING.md).
