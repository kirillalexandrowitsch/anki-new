# Атомарная оценка и Undo T020

[Движок](REVIEW_ENGINE.md) · [Экран](STUDY_SESSION.md) · [Очередь](STUDY_QUEUE.md)

`RateCard` / `UndoRating` используют Core-порт `ReviewRepository`. SQLite-адаптер
работает через единственный CollectionWriter. Features не выполняет SQL. Реальное
занятие открывается явной кнопкой «Начать занятие»; пробное занятие остаётся
отдельным синтетическим режимом. Полные Today-метрики, завершение и восстановление
сессий относятся к T022/T023; здесь сохраняется минимальная очередь и политика.

Команда оценки содержит sessionID, commandID, CardID, expected schedule revision,
scheduleEpoch, Grade, event time, durationMs (0…60000), seed. Writer сначала ищет
processed_commands: та же команда возвращает сохранённый ReviewReceipt, другой
payload с прежним commandID отклоняется. Это действует и после Undo: replay старой
оценки возвращает исторический результат, не применяет её снова.

В одной транзакции проверяются активная scheduled-сессия, показанный session item,
revision/epoch, свежая доступность и квоты QueueBuilder на время события и записи.
Пока поддержан доставленный Basic template; удалённые или неподдержанные шаблоны
не показываются. Scheduler получает сохранённые параметры и фиксированные
время/seed команды. Время расчёта квантуется до миллисекунд SQLite; receipt содержит
фактически сохранённые snapshots. Атомарно записываются все поля расписания,
ReviewLog, stage=rated / eligibleAt элемента очереди, session revision/duration,
полный SchedulingMetadata и quota event в domain_events, результат processed command.
Ошибки не продвигают экран; UI повторяет сохранённую команду.

Показ следующего вопроса тоже записывает session_items внутри короткой транзакции.
При повторном открытии ответ скрыт; future learning не становится готовым раньше
срока. Generation проверяется владельцем writer; закрытый writer отклоняет старый
service. История хранит Note identity и путь колод на время события, day key,
timezone и границу sibling bury. QueueBuilder читает voidedBy при каждом решении,
поэтому Undo освобождает уникальную квоту и отменяет соответствующее sibling bury
без перезаписи независимого buriedUntil карточки.

Undo имеет собственный commandID, ratingID и event time. Разрешена последняя
эффективная оценка этой сессии при совпадении полной текущей schedule с after,
session revision, Card/Note revision и доступности. Поздняя оценка, reset epoch,
перемещение/удаление/приостановка или несовместимая правка дают конфликт без записи.
Компенсация восстанавливает before с новой, монотонно растущей revision, помечает
исходный ReviewLog через voidedBy, восстанавливает прежний item в answer и
возвращает текущий вопрос в queued. Отдельный review.undone и processed result
пишутся той же транзакцией. Статистика effectiveStatistics считает только
`voidedBy IS NULL`, включая DISTINCT card identity и duration; исходный log остаётся.

Экран показывает «Отменить оценку» только для реального review service. Успех
возвращает прежнюю карточку с раскрытым ответом и новой revision, уменьшает число
подтверждённых оценок. Повтор отмены после неопределённой ошибки сохраняет тот же
commandID. При конфликте UI сообщает об изменившихся данных. Во время Undo
используется committing gate; повторная оценка и второй Undo недоступны.

Существующая SQLite v1-схема достаточна: старые миграции и пользовательские данные
не переписываются. Новых зависимостей, платных сервисов или разрешений нет.
Проверки используют только временные синтетические коллекции, включая реальный
выход дочернего процесса через _exit до/после commit и восстановление WAL.
