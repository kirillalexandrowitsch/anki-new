# T097 · Проверить обновление и аварийный откат

**Статус:** запланировано. **Этап:** M5. **Сложность:** L.

## Результат

Обновлять приложение с сохранением коллекций и копий.

## Зависимости

[T053](T053.md) · [T054](T054.md) · [T083](T083.md) · [T096](T096.md)

## Область изменений

Предлагаемые файлы/модули: `Tests/Upgrade; docs/UPGRADE.md`. Путь уточняется при создании исходников без изменения границ ответственности.

## Как выполнить

1. Установить новую сборку поверх тестовой beta со всеми схемами и media.
2. Проверить backup-before-migration, registry/bookmarks и контроль unknown newer schema.
3. Описать rollback installer+старой копии; не обещать автоматическое чтение новой БД старым бинарником.

## Критерии готовности

- [ ] После обновления counts/history/media совпадают ожидаемому результату.
- [ ] Сбой миграции имеет воспроизводимый путь возврата к копии.

## Проверка

Upgrade fixtures, оборванная миграция, manual reinstall и restore в отдельную папку.

## Дизайн-референсы

Инфраструктурная задача без отдельного растрового экрана. Контракт задают [ARCHITECTURE.md](../ARCHITECTURE.md) и [DATA_MODEL.md](../DATA_MODEL.md).

## Ограничения

Выполнять только описанную область. Общие правила сохранения, reveal/ratings и отмены — в [PRODUCT.md](../PRODUCT.md) и [REVIEW_ENGINE.md](../REVIEW_ENGINE.md); файловые операции — в [INTEGRATIONS.md](../INTEGRATIONS.md). Новое поведение документировать до изменения связанных контрактов. Не считать задачу выполненной без её критериев и проверки.

Следующая по номеру: [T098](T098.md). Начинать её можно только после собственных зависимостей.
