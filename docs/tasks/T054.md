# T054 · Проверить миграции и recovery открытия

[Оглавление плана](../README.md) · [Все задачи](../TASKS.md) · [Порядок разработки](../ROADMAP.md)

**Статус:** запланировано. **Этап:** M3. **Сложность:** L.

## Результат

Обновлять пользовательскую коллекцию с проверенной копией.

## Зависимости

[T006](T006.md) · [T007](T007.md) · [T011](T011.md) · [T053](T053.md)

## Область изменений

Предлагаемые файлы/модули: `Infrastructure/Migrations; Features/Onboarding`. Путь уточняется при создании исходников без изменения границ ответственности.

## Как выполнить

1. Создать fixtures каждой поддержанной старой схемы.
2. Перед миграцией проверить место/backup, показывать этап и запретить конкурирующую запись.
3. Более новую схему отклонять, повреждённую открывать только диагностическим безопасным путём.

## Критерии готовности

- [ ] Неудачная миграция сохраняет исходный контейнер и рабочую копию.
- [ ] Версия схемы повышается только после commit.

## Проверка

Upgrade всех fixtures, unknown future version и прерывание процесса во время миграции.
