# T006 · Создать схему SQLite и миграции

[Оглавление плана](../README.md) · [Все задачи](../TASKS.md) · [Порядок разработки](../ROADMAP.md)

**Статус:** готово. **Этап:** M0. **Сложность:** L.

## Результат

Поднять versioned хранилище первоначальных сущностей.

## Зависимости

[T003](T003.md) · [T005](T005.md)

## Область изменений

Предлагаемые файлы/модули: `Infrastructure/Persistence/, Migrations/`. Путь уточняется при создании исходников без изменения границ ответственности.

## Как выполнить

1. Создать таблицы DATA_MODEL.md для коллекции, колод, Notes/Cards, расписания, сессий, журнала и медиа.
2. Настроить DatabasePool, foreign keys, индексы, частичную уникальность и метаданные схемы.
3. Добавить migrator с запретом записи неизвестной более новой схемы; пока без пользовательских операций миграции UI.

## Критерии готовности

- [ ] Пустая БД создаётся повторяемо, целостность и ограничения проверяются.
- [ ] Ошибка миграции не маркируется успешной версией.

## Проверка

Создание/reopen временной file-БД, constraint tests и намеренно оборванная тестовая миграция.

## Дизайн-референсы

Инфраструктурная задача без отдельного растрового экрана. Контракт задают [ARCHITECTURE.md](../ARCHITECTURE.md) и [DATA_MODEL.md](../DATA_MODEL.md).

## Ограничения

Выполнять только описанную область. Общие правила сохранения, reveal/ratings и отмены — в [PRODUCT.md](../PRODUCT.md) и [REVIEW_ENGINE.md](../REVIEW_ENGINE.md); файловые операции — в [INTEGRATIONS.md](../INTEGRATIONS.md). Новое поведение документировать до изменения связанных контрактов. Не считать задачу выполненной без её критериев и проверки.
