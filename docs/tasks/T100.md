# T100 · Зафиксировать финальную версию и восстановление

[Оглавление плана](../README.md) · [Все задачи](../TASKS.md) · [Порядок разработки](../ROADMAP.md)

**Статус:** запланировано. **Этап:** M5. **Сложность:** M.

## Результат

Оставить воспроизводимую рабочую версию и понятный способ восстановления.

## Зависимости

[T099](T099.md)

## Область изменений

Предлагаемые файлы/модули: `docs/LOCAL_BUILD.md; docs/UPGRADE.md; Git history`. Путь уточняется при создании исходников без изменения границ ответственности.

## Как выполнить

1. Зафиксировать Git tag/commit, точные версии инструментов, локальную .app и инструкцию её пересборки.
2. Сверить task statuses, отчёты, roadmap и compatibility limitations; синхронизировать GitHub.
3. Описать откат к предыдущей версии кода и отдельно восстановление совместимой базы из backup; публичную публикацию не выполнять.

## Критерии готовности

- [ ] Владелец может пересобрать и установить приложение по инструкции.
- [ ] Есть проверенный путь восстановления приложения и данных; история и отчёты доступны в приватном репозитории.

## Проверка

Пересборка из зафиксированного Git состояния и контрольный restore в отдельную тестовую коллекцию.

## Дизайн-референсы

Инфраструктурная задача без отдельного растрового экрана. Контракт задают [ARCHITECTURE.md](../ARCHITECTURE.md) и [DATA_MODEL.md](../DATA_MODEL.md).

## Ограничения

Выполнять только описанную область. Общие правила сохранения, reveal/ratings и отмены — в [PRODUCT.md](../PRODUCT.md) и [REVIEW_ENGINE.md](../REVIEW_ENGINE.md); файловые операции — в [INTEGRATIONS.md](../INTEGRATIONS.md). Новое поведение документировать до изменения связанных контрактов. Не считать задачу выполненной без её критериев и проверки.
