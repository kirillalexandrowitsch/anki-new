## Результат

Сделать проверки воспроизводимыми с начала разработки.

## Зависимости

[T002](T002.md) · [T005](T005.md) · [T006](T006.md)

## Область изменений

Предлагаемые файлы/модули: `Tests/Fixtures/ и scripts/`. Путь уточняется при создании исходников без изменения границ ответственности.

## Как выполнить

1. Создать synthetic fixtures с кириллицей, несколькими колодами, расписаниями и медиа.
2. Ввести TestClock, временную file-БД, isolated temp directories и fault injection hooks.
3. Добавить локальный check script с package tests и app build; сохранить seed и команды запуска.

## Критерии готовности

- [ ] Проверки не читают личную коллекцию и не требуют сети после resolve.
- [ ] Падение теста сохраняет полезную диагностику без пользовательских текстов.

## Проверка

Запустить check script дважды на чистом fixture; результаты детерминированы.

## Дизайн-референсы

Инфраструктурная задача без отдельного растрового экрана. Контракт задают [ARCHITECTURE.md](../ARCHITECTURE.md) и [DATA_MODEL.md](../DATA_MODEL.md).

## Ограничения

Выполнять только описанную область. Общие правила сохранения, reveal/ratings и отмены — в [PRODUCT.md](../PRODUCT.md) и [REVIEW_ENGINE.md](../REVIEW_ENGINE.md); файловые операции — в [INTEGRATIONS.md](../INTEGRATIONS.md). Новое поведение документировать до изменения связанных контрактов. Не считать задачу выполненной без её критериев и проверки.
