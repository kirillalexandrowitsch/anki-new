# T008 · Создать команды записи и репозитории

[Оглавление плана](../README.md) · [Все задачи](../TASKS.md) · [Порядок разработки](../ROADMAP.md)

**Статус:** готово. **Этап:** M0. **Сложность:** M.

## Результат

Обеспечить единый путь изменения коллекции.

## Зависимости

[T006](T006.md) · [T007](T007.md)

## Область изменений

Предлагаемые файлы/модули: `Core/Ports/; Infrastructure/Repositories/`. Путь уточняется при создании исходников без изменения границ ответственности.

## Как выполнить

1. Реализовать CollectionWriter и короткие транзакции без await внутри closure.
2. Ввести expectedRevision, commandID, processed_commands и типизированные errors.
3. Разделить repository ports по предметным сценариям; возвращать Sendable DTO, не GRDB connection.

## Критерии готовности

- [ ] Повтор commandID не применяет операцию второй раз.
- [ ] Конфликт revision возвращается вызывающему коду без молчаливой перезаписи.

## Проверка

Транзакционный rollback, duplicate command и конкурентные попытки сохранения одной сущности.

## Дизайн-референсы

Инфраструктурная задача без отдельного растрового экрана. Контракт задают [ARCHITECTURE.md](../ARCHITECTURE.md) и [DATA_MODEL.md](../DATA_MODEL.md).

## Ограничения

Выполнять только описанную область. Общие правила сохранения, reveal/ratings и отмены — в [PRODUCT.md](../PRODUCT.md) и [REVIEW_ENGINE.md](../REVIEW_ENGINE.md); файловые операции — в [INTEGRATIONS.md](../INTEGRATIONS.md). Новое поведение документировать до изменения связанных контрактов. Не считать задачу выполненной без её критериев и проверки.
